# Hyper Render v24 — ملخص التغييرات

## ⚠️ لازم تعملها الأول (أمان)
1. **غيّر توكن بوت تليجرام فوراً** من @BotFather (`/revoke`). كان مكتوب جوه `server.js` في ريبو GitHub عام،
   وحتى بعد حذفه من الكود هو لسه موجود في تاريخ git، فاعتبره مكشوف.
2. حط القيم دي كـ **Secrets** في الـ Space (مش في الكود): `TELEGRAM_BOT_TOKEN` (الجديد)، `TELEGRAM_CHANNEL_ID`
   (كان مكتوب في config.js)، و`RENDER_API_KEY` (لو فاضي السيرفر مفتوح لأي حد).
3. ارفع نفس الملفات على GitHub والـ Space، وامسح مجلد `files/` المكرر من الريبو. متعملش overwrite لـ README بتاع الـ Space.

## ⚡ وضع "خلفية فقط" (جديد، للفيديوهات العريضة على يوتيوب)
فيديو الخلفية + الصوت بس، **بدون أي نص ولا تدرج ولا علامات**. مفيش رسم فريمات ولا خطوط ولا overlay.
اللي بيتعالج الصوت بس، والفيديو بيتنسخ (stream copy) بدون فك ولا إعادة تشفير.

```json
POST /render
{
  "backgroundOnly": true,
  "aspectRatio": "16:9",
  "backgroundUrl": "https://.../background.mp4",
  "verses": [ { "audio": "https://.../surah.mp3" } ]
}
```
- `verses[].text` اختياري. لو كل العناصر ليها **نفس رابط الصوت** (ملف سورة/محاضرة كاملة) بيتستخدم الملف كله بدون تقسيم
  أو تقليم. لو الروابط مختلفة بيتوصلوا بالترتيب.
- الخلفية: فيديو (`backgroundUrl`)، أو عدة فيديوهات (`backgroundUrls`)، أو صورة، أو `color:#RRGGBB`.
- فيديو الخلفية بيتكرر لحد طول الصوت. أحسن نتيجة وأسرع: **H.264 / yuv420p / 1920×1080 (للعريض) أو 720×1280 (للطولي)**.
  لو الفيديو بمواصفات تانية بيتعمل له إعادة تشفير مرة واحدة (بتتخزّن في الكاش، وبتتقلّم على المدة المطلوبة).
- الصورة واللون: بيتشفّر مقطع ثابت ~10 ثواني مرة واحدة وبيتكرر بالنسخ (وقت التشفير ثابت مهما طال الفيديو).
- **حجم الملف = معدل بيانات الفيديو الأصلي** (لأن مفيش إعادة تشفير). لو عايز ملف أصغر، جهّز الخلفية بمعدل بيانات أقل.
- الصوت بيعدّي على نفس فلتر الصوت الموجود في النسخة العادية (بدون تعديل).
- لو الملف النهائي أكبر من 49MB بنتخطى رفع تليجرام بدل ما نضيّع وقت (`TELEGRAM_MAX_MB`) — الرابط الأساسي `/download` شغال.

| الحالة (CPU واحد) | الوقت |
|---|---|
| 16:9، خلفية فيديو 1080p/h264، صوت 30 ثانية | 2.5 ث (1.3 ث مع الكاش) |
| 16:9، **صوت 10 دقايق** | **22.4 ث** (أغلبها معالجة الصوت) |
| طولي 720×1280 (الخلفية 1080p → إعادة تشفير مرة واحدة) | 1.5 ث (مع الكاش) |
| صورة خلفية 16:9، صوت 30 ث | 5.1 ث |
| لون خلفية 16:9، صوت 30 ث | 2.5 ث |
| عدة خلفيات 16:9 (بعد الكاش) | 3.1 ث |
للمقارنة: نفس الفيديو العريض بالنص كان بياخد ~12.6 ثانية لكل 20 ثانية فيديو (حوالي 25 دقيقة لساعة على CPU واحد).
معالجة الصوت حوالي 37× أسرع من الوقت الحقيقي، فساعة صوت تقريباً دقيقة ونص دقيقة على CPU واحد (تقدير من قياس 10 دقايق).
الحالة الأبطأ: أول مرة لعدة خلفيات أو خلفية بمواصفات مختلفة (إعادة تشفير مرة واحدة)، وبعدها الكاش بيخليها فورية.

## خلفية الفيديو (الأهم ليوتيوب)
اللي اتغيّر في مسار خلفية الفيديو:
- **الفريمات المتطابقة:** في القالب الافتراضي `activeWordIndex` مش بيأثر على الرسم أصلاً، فكل فريمات "كلمة بكلمة"
  كانت صور متطابقة والسيرفر بيرسمها عدد الكلمات مرة. دلوقتي فريم واحد للسطر. النتيجة النهائية متطابقة.
- **فريمات الـ fade:** فلتر الظل (`textGlow`) بياخد ~75% من وقت رسم الفريم. دلوقتي طبقة النص بتتحسب مرة لكل سطر
  وكل فريم انتقال = ضرب الألفا + دمج (فرق البكسلات ≤ 3/255 على PNG). الحركات اللي بتغيّر المكان/الحجم
  (slide/zoom/bounce/flip/blur/wave) أو وجود filter/overlay بتفضل على المسار الأصلي. أي خطأ = رجوع تلقائي للأصلي.
- **تجهيز الخلفية:** بيتقلّم على المدة المطلوبة بس (كان بيعيد تشفير الفيديو كله بمهلة ثابتة 5 دقايق، فخلفية طويلة
  ممكن كانت تفشل). المهلة بقت بتتناسب مع الطول.
- **التوازي:** تجهيز الخلفية ودمج الصوت بيشتغلوا جنب رسم الفريمات (مفيد لما السيرفر فيه أكتر من CPU).
- رسم PNG الشفاف مباشرة من الـ SVG بدل create+composite.

## باقي التحسينات
**سرعة:** صورة الشيخ وخلفية الدوسري بتتصغّر مرة واحدة، وخلفية الصورة بتتجهّز raw مرة واحدة، حجم دفعة الفريمات
حسب الـ CPU، FFmpeg بدون shell، مفيش حفظ للخطوط base64 داخل كل فريم.

**أخطاء اتصلحت:**
- رابط `/download` كان 404 بعد كل رندرة ناجحة (الملف كان بيتمسح بعد رفعه لتليجرام). دلوقتي الملف بيفضل لحد التنظيف
  الدوري، والـ job فيه `telegramFileId` و`telegramUrl`، وفيه تحويل تلقائي لتليجرام لو الملف المحلي اتمسح.
- فشل `ffprobe` كان بيطلّع فيديو 5 ثواني بصمت. دلوقتي بيفشل برسالة واضحة.
- `getFile` في تليجرام كان بيفشل للملفات +20MB ويرجّع null رغم نجاح الرفع. اتشال.
- مهلة رفع تليجرام 10 ثواني بقت 180 (`TELEGRAM_UPLOAD_TIMEOUT_MS`). (ملاحظة: بوت تليجرام حده 50MB للفيديو.)
- الخطوط بتتحمّل كلها وقت الإقلاع + `fc-cache` مرة واحدة، وأسماء Impact / Montserrat-Black / SurahNameV2 ليها alias.
- الملفات المؤقتة بتتمسح فوراً بعد النجاح (كانت 30 دقيقة).

**أمان:** شيل التوكن من الكود ومن اللوج، `/debug/*` مقفولة إلا بـ `ENABLE_DEBUG=1` + API key، حماية path traversal في
`/download`، تتبّع redirects يدوياً (https فقط، مش IP، مش localhost) + سقف حجم التحميل، اسم الخط من قايمة معروفة،
حد أقصى للخلفيات المتعددة، وطابور له حد (503 + Retry-After). شكل الـ API نفسه ما اتغيرش.

## متغيرات بيئة جديدة (كلها اختيارية)
| المتغير | الافتراضي | الغرض |
|---|---|---|
| `X264_PRESET` | `ultrafast` | الأسرع. (`veryfast` = ملف أصغر بكتير بس ~2x وقت التشفير في قياسي) |
| `X264_CRF` | `23` | الجودة. رفعه لـ 27–28 مع ultrafast بيصغّر الملف للنص تقريباً بنفس السرعة |
| `OUTPUT_FPS` | `0` | 0 = زي v23 |
| `FRAME_BATCH` | عدد الـ CPU (2–6) | فريمات بالتوازي |
| `MAX_QUEUE_SIZE` | `20` | أقصى طلبات منتظرة |
| `MAX_DOWNLOAD_MB` | `400` | سقف حجم أي تحميل |
| `KEEP_LOCAL_AFTER_TELEGRAM` | `1` | `0` = امسح النسخة المحلية وخلّي الرابط `/telegram-proxy` |
| `TELEGRAM_MAX_MB` | `49` | أكبر ملف بنحاول نرفعه لتليجرام |
| `ENABLE_DEBUG` | فاضي | يفتح `/debug/*` |
| `EXTRA_ALLOWED_DOMAINS` | فاضي | نطاقات إضافية للتحميل |

## القياسات (سيرفر اختبار بـ CPU واحد، أصول اصطناعية، فيديو ≈ 20 ثانية إلا لو مكتوب غير كده)
| الحالة | v23 | v24 |
|---|---|---|
| خلفية فيديو، طولي، الخلفية مخزّنة | 17.4 ث | 8.8 ث |
| خلفية فيديو، 16:9 (1080p)، الخلفية مخزّنة | 25.7 ث | 12.6 ث |
| خلفية فيديو، 16:9، أول مرة (مقطع 10 ث) | 26.2 ث | 16.5 ث |
| خلفية فيديو طويلة (90 ث) → إخراج 20 ث، أول مرة | 56.2 ث | 33.6 ث |
| قالب افتراضي + صورة خلفية 4000×3000 (30 ث) | 60.8 ث | 11.7 ث |
| قالب افتراضي + لون خلفية (30 ث) | 8.5 ث | 4.5 ث |
| فريم قالب مشغّل بصورة 1600px (فريم واحد) | ~150 ms | ~55 ms |

مرحلة FFmpeg النهائية بقت هي الحد الأدنى: في 1080p حوالي 0.4 ثانية معالجة لكل ثانية فيديو على CPU واحد
(فك الخلفية ≈ 3.1 ث + تشفير x264 ≈ 4.3 ث لكل 20 ث). فيديو 16:9 ساعة ≈ 25 دقيقة على CPU واحد، وعلى 2 vCPU
غالباً أقل، بس ده تقدير مش قياس. تقليل الدقة (مثلاً 720p) هو الرافعة الوحيدة الكبيرة المتبقية.

حجم الملف (خلفية اصطناعية عالية التفاصيل، 20 ث 1080p): `ultrafast crf23` ≈ 16.9MB / 7.4 ث، `ultrafast crf28` ≈ 8.1MB / 7.2 ث،
`veryfast crf26` ≈ 1.8MB / 14.7 ث. فيديو حقيقي هيدّي أرقام مختلفة، جرّب على خلفياتك.

الأرقام على الـ Space (عادةً 2 vCPU) ممكن تختلف، وصور الشيخ بتتحمل من Cloudinary وهو محجوب في بيئة الاختبار
فمكسب قوالب المشغّل اتقاس على فريم واحد بس.
