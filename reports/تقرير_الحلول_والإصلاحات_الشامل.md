## 1. المشكلة الأولى: انقطاع وصول خلفيات الفيديو السحابية عبر تليجرام

### 🛑 وصف المشكلة:
توقف استلام الفيديوهات المرفوعة على قناة تليجرام المخصصة للخلفيات السحابية منذ يوم 21-07، حيث تم رفع فيديوهات كثيرة بعدها ولم تظهر في الموقع إطلاقاً.

### 🔍 التشخيص التقني الدقيق:
1. تم فحص استجابة الـ Telegram Bot API مباشرة عبر مسار `getWebhookInfo`، وتبين ما يلي:
   ```json
   {
     "ok": true,
     "result": {
       "url": "",
       "has_custom_certificate": false,
       "pending_update_count": 16
     }
   }
   ```
2. **السبب الجذري**: رابط الـ Webhook كان ممسوحاً ومفرغاً تماماً (`"url": ""`) في إعدادات بوت تليجرام.
3. تليجرام كان يحتجز **16 فيديو وتحديثاً معلقاً** في طابور الانتظار الداخلي (`pending_update_count: 16`) دون إرسالها إلى خادم الموقع.
4. عند فحص محتوى التحديثات المعلقة عبر `getUpdates`، اتضح أن الفيديوهات كانت محولة (Forwarded) من قناة *"خلفيات جاهزه للتصميم"* وكانت بدون كابشن أو هاشتاجات.

### 🛠️ الحل البرمجي المنفذ:
1. تم تفعيل الويب هوك وإعادة ربطه بخادم الإنتاج بالرابط الدقيق المعتمد:
   ```text
   https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=https%3A%2F%2Fyaqeenalquran.online%2Fapi%2Ftelegram-webhook%2F
   ```
   *(تم تثبيت الشرطة المائلة `/` لتجنب خطأ 308 Permanent Redirect الخاص بـ Next.js trailingSlash).*
2. بمجرد تفعيل الرابط، قام تليجرام فوراً بتفريغ وإرسال كامل الـ 16 تحديثاً إلى السيرفر دفعة واحدة.
3. هبطت قيمة `pending_update_count` من 16 إلى **0**، وأرجع السيرفر كود النجاح `200 OK` لجميع المنشورات.
4. تمت معالجة وتخزين جميع الفيديوهات في مجموعة `backgrounds` بقاعدة بيانات Firestore.

### 📌 مكان ظهور الفيديوهات وكيفية التصنيف:
* نظراً لأن الفيديوهات المرفوعة كانت بدون وصف (كابشن)، فإن الكود يطبق القيم الافتراضية:
  * **القسم**: يذهب تلقائياً لقسم **"طبيعة"**.
  * **العنوان**: يكون بصيغة `فيديو سحابي 9/9/2026`.
* **للتصنيف المستقبلي**: يتم كتابة الهاشتاج المطلوب في كابشن الفيديو عند رفعه بالقناة (مثل `#مساجد`، `#بحار`، `#غروب`، `#جبال`، `#غابات`، `#سماء`).

## 2. المشكلة الثانية: خطأ أيقونة المانيفست (Manifest Icon) و 404 Network Error

### 🛑 وصف المشكلة:
ظهور خطأ أحمر في الكونسول عند فتح الموقع أو لوحة التحكم:
```text
Error while trying to use the following icon from the Manifest: https://yaqeenalquran.online/logo/logo.png?v=25 (Download error or resource isn't a valid image)
Failed to load resource: the server responded with a status of 404 (Network error)
```

### 🔍 التشخيص التقني:
1. في ملف `public/manifest.json`، كانت مسارات الأيقونات مكتوبة بالبارامتر `?v=25`.
2. بينما ملف الـ Service Worker في `public/sw.js` يقوم بحفظ الأيقونة في الكاش بالمسار الصافي `/logo/logo.png`.
3. عندما يطلب المتصفح `/logo/logo.png?v=25`، يفشل الـ Service Worker في مطابقة الرابط مع الكاش في السطر 164، وفي حال عدم توفر الاتصال أو تعذر الجلب، يتم إرجاع كود 404 مع نص `Network error` في السطر 177:
   ```javascript
   return new Response('Network error occurred', { status: 404, statusText: 'Network error' });
   ```

### 🛠️ الحل البرمجي المنفذ:
1. **في `public/manifest.json`**: إزالة `?v=25` وتوحيد مسارات الأيقونات الصافية:
   ```json
   {
     "src": "/logo/logo.png",
     "sizes": "192x192",
     "type": "image/png",
     "purpose": "any"
   }
   ```
2. **في `src/app/layout.tsx`**: تحديث صور الـ OpenGraph والـ Twitter لتطابق نفس المسار بدون استعلام.
3. **في `public/sw.js`**:
   * تفعيل خاصية المطابقة متجاهلة الاستعلام:
     ```javascript
     caches.match(request, { ignoreSearch: true })
     ```
   * ترقية إصدار الكاش لضمان تحديث المتصفحات فوراً.

## 3. المشكلة الثالثة: تحذيرات مكتبة التحريك GSAP (Target not found)

### 🛑 وصف المشكلة:
ظهور تحذيرات متكررة في كونسول المتصفح:
```text
GSAP target .admin-stagger-card not found. https://gsap.com
GSAP target not found. https://gsap.com
```

### 🔍 التشخيص التقني:
1. في `src/components/AdminPanel.tsx`، يتم استدعاء دالة الأنيميشن بمجرد تحقق شرط الأدمن `isAdmin`:
   ```typescript
   gsap.fromTo(".admin-stagger-card", { y: 35, opacity: 0 }, ...);
   ```
   وعند التواجد في صفحات فرعية (مثل صفحة الخلفيات `/admin/backgrounds`)، لا تكون عناصر الإحصائيات موجودة في الـ DOM، فتقوم مكتبة GSAP بإصدار تحذير.
2. في `src/components/AppInitializer.tsx`، كانت تمرر مصفوفة عناصر تتضمن مراجع قد تكون `null` قبل رسم الواجهة (مثل `logoImgRef` أو `textContainerRef`).

### 🛠️ الحل البرمجي المنفذ:
1. **في `AdminPanel.tsx`**: إضافة فحص تحقق صريح لوجود البطاقات في الصفحة:
   ```typescript
   const cards = document.querySelectorAll(".admin-stagger-card");
   if (cards.length > 0) {
     gsap.fromTo(cards, ...);
   }
   ```
2. **في `AppInitializer.tsx`**: تصفية مراجع الـ DOM والتأكد من أنها معرفة قبل تمريرها لمكتبة GSAP:
   ```typescript
   if (!overlayRef.current) return;
   const textTargets = [textContainerRef.current, authorRef.current, skipBtnRef.current].filter(Boolean);
   if (textTargets.length > 0) gsap.set(textTargets, { opacity: 0, y: 15 });
   ```

## 5. التحديث الخامس: استعادة تفريغ فيديوهات تليجرام الـ 45 المعلقة وإلغاء الهاشتاجات نهائياً
**تاريخ التحديث**: 21 سبتمبر 2026

### 🛑 وصف المشكلة:
1. توقف استقبال الفيديوهات المرفوعة حديثاً في قناة "مخزن فيديوهات يقين" على تليجرام، وتراكم **45 فيديو معلقاً** في طابور تليجرام دون وصولها لقاعدة البيانات ولا لمحرر الموقع أو لوحة الأدمن.
2. اشتراط الكود السابق لوجود علامات الهاشتاج (`#`) في كابشن الفيديو للتعرف على القسم والتاغات، وفي حال الرفع بدون `#` كان الفيديو يُعامل كافتراضي أو يفقد التصنيف الدقيق.
3. عدم دعم مقاطع الفيديو المرفوعة كملف (Document).

### 🛠️ الحل البرمجي المنفذ:
1. **استعادة الويب هوك وتفريغ الفيديوهات المعلقة**:
   * تم إعادة تفعيل الويب هوك الرسمي بالرابط المباشر `https://yaqeenalquran.online/api/telegram-webhook/`.
   * قام تليجرام فوراً بإرسال وتفريغ كامل الـ 45 فيديو المعلقة دفعة واحدة إلى خادم الموقع.
   * هبطت قيمة `pending_update_count` من 45 إلى **0**.
   * تم تخزين جميع الفيديوهات الـ 45 بنجاح في مجموعة `backgrounds` بقاعدة بيانات Firestore ليرتفع الإجمالي من 104 إلى **149 خلفية**.
2. **إلغاء الحاجة للهاشتاجات نهائياً**:
   * تم تعديل كود `src/app/api/telegram-webhook/route.ts` لإزالة أي اعتماد على علامة الهاشتاج `#`.
   * تم بناء محرك تطابق دلالي ذكي يفحص الكلمات العربية الطبيعية في وصف الفيديو (مثل: بحر، شاطئ، أمواج -> بحار | مسجد، كعبة، حرم -> مساجد | جبال، صخور -> جبال ... إلخ) ويعين القسم تلقائياً.
   * مسح وتجريد رمز `#` من العناوين والتاغات تماماً حتى لا يظهر أي هاشتاج في واجهة المستخدم.
3. **دعم الفيديوهات المرسلة كملف (Document)**:
   * تم توسيع شرط فحص الفيديو ليشمل `post.video` وأيضاً `post.document` إذا كان من نوع `video/*`.
